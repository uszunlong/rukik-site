名为“sshole”的漏洞允许黑客通过 SSH 访问 Linux 设备

Ars Technica · 2026-11-05 · 单一来源

RUKIK 新闻摘要

安全领域近日披露了一个名为“sshole”的新漏洞，该漏洞允许黑客直接通过 SSH 远程访问受影响的 Linux 设备。目前已知某些 Alpine Linux 的配置受到该漏洞的影响，同时其他 Linux 发行版也可能存在同样的风险。相关技术细节与影响范围仍在持续评估与确认中，官方及安全研究人员尚未公布更多关于该漏洞的具体利用方式、修补进展以及是否已有实际攻击发生等详细信息。对于使用 Alpine 及其他受影响配置的系统管理员而言，需要密切关注后续的安全公告与补丁发布，以防范潜在的远程访问威胁。

RUKIK 专业解读

技术突破在哪里

这次风险点不在“暴力猜密码”，而在认证边界本身。公开信息显示，问题出现在 OpenSSH 与 musl 的某些交互上，攻击者可能通过输入异常长的密码，进入原本被配置为禁止密码登录的账户。外部披露还提到，这类情况已在部分 Alpine Linux 配置中得到确认，而 Alpine 恰好是容器、边缘设备、轻量化系统里常见的发行版之一。这意味着，真正值得警惕的不是某个普通登录失败，而是“明明以为关掉了密码入口，结果入口还在”。

与既有方案的实质差异

很多远程入侵都依赖弱口令、密钥泄露或运维误配置；这类问题本质上还是“凭证被猜到或被拿到”。而这次更像是认证流程出现了绕行路径：配置表面上是安全的，实际却可能被特定条件触发。对运维团队来说，这和传统“把密码设复杂一点”不是一个层级的问题，因为即使账户没有可用密码，风险也可能存在。值得注意的是，新闻并未显示所有 Linux 都受影响，它更像是“特定组件组合下的实现缺陷”，而不是 SSH 这类远程登录机制整体失效。

距离实际应用还有多远（成熟度）

从成熟度看，这还处在“高关注、但边界未完全定型”的阶段。已证实的是：部分 Alpine 配置受影响，其他发行版也可能存在类似风险；尚未明确的是，完整影响范围、修补进展，以及是否已经出现真实攻击。安全公司 Check Point 的研究人员进一步表示，利用能否成立与账户使用的散列方式有关，并且账户需要处于激活状态，否则攻击会失败。这说明它不是“一把钥匙开所有门”的通杀型漏洞，现实可利用性依赖环境细节。

存在哪些限制

限制恰恰决定了风险排序。公开线索显示，受影响环境与 musl、OpenSSH、是否启用 PAM、账户状态和散列配置都有关系，因此不是所有 Alpine，也不是所有 Linux 服务器都会中招。这意味着，短期内最需要排查的，通常是追求轻量化、精简依赖、关闭 PAM 或采用特定认证组合的系统，例如容器宿主机、边缘节点、嵌入式 Linux 设备。对大型企业环境来说，风险未必最低，但排查重点应先落在“看似简洁安全”的那批配置上，而不是笼统地把所有 SSH 主机一视同仁。

为什么与您有关

该漏洞直接威胁 Linux 设备的远程访问安全，可能对使用相关发行版的服务器和嵌入式系统造成安全隐患。

重要事实

  • 漏洞被命名为“sshole”，允许黑客通过 SSH 访问 Linux 设备。
  • 某些 Alpine Linux 的配置受到影响，其他发行版也可能受影响。
